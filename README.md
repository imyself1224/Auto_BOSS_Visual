# Auto BOSS Visual

用**纯视觉**驱动浏览器，在 BOSS 直聘上按你的简历自动筛岗位、自动打招呼（点「立即沟通」）。
视觉定位和岗位匹配全部交给 DeepSeek，不解析页面 DOM。

- 🖼️ **纯视觉**：截图 + 归一化网格 → 模型报坐标 → CDP 发可信鼠标事件。页面改版、薪资字体加密都不怕。
- 🎯 **按简历判档**：你提供一份「求职者画像」，模型把每个岗位跟它对比，分成 最匹配 / 次匹配 / 可转投 / 产品 / 测试 / 不可用，按档位先后投递。
- 🧮 **硬条件过滤**：只投实习、日薪下限、城市、地区加分，薪资统一折算成日薪再比。
- 🛑 **安全阀**：默认演练不发送；验证码 / 平台额度提示立即停机；去重库保证不重复打扰。
- 📱 **QQ 遥控（可选）**：小号推送每条投递结果和本次检索关键词，大号发 `/投递`、`/投递 关键词`、`/停止` 远程控制。
- 📦 **只依赖一个 `websockets`**，其余全是 Python 标准库。

## ⚠️ 使用前必读

这个工具会代替你做出**对你账号有真实后果**的操作：

1. **违反平台协议。** BOSS 直聘《用户协议》禁止使用机器人、爬虫等自动化手段。
2. **存在封号风险。** 轻则警告、限制功能，重则冻结乃至永久封禁。
3. **每日额度由平台控制**，用尽时会弹提示，程序检测到会立即停机。
4. **先小批量试。** 第一次用 `--limit 1` 看着它把一个招呼准确发出去，再放开跑。

项目默认 `dry_run = true`（只筛选、不发送），想真发必须显式加 `--live` 并输入 `yes` 确认。

**仅供个人求职学习使用，请勿商用或高频群发。使用后果自负。**

## 快速开始

### 1. 安装

需要 **Python 3.11+**（用到 `tomllib`）和 **Edge 或 Chrome**（自动探测，Windows 自带的 Edge 即可）。

```bash
git clone https://github.com/imyself1224/Auto_BOSS_Visual.git
cd Auto_BOSS_Visual
pip install -r requirements.txt
```

### 2. 填 API Key

```bash
cp .env.example .env
```

编辑 `.env`，填入在 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 申请的 key（等号两边不要空格、不要引号）：

```ini
DEEPSEEK_API_KEY=sk-你的key
```

> `.env`、`resume/` 下的个人文件、浏览器登录态、日志、截图、数据库都已在 `.gitignore` 里，不会被提交。

### 3. 生成求职者画像 `resume/kb.md`

这是**判断岗位能不能投的唯一依据**，必须有。用下一节的提示词让 DeepSeek 读你的简历生成，几分钟搞定。

### 4. 按自己的情况改 `config.toml`

至少看一眼这几项（详见[配置说明](#配置说明)）：

| 配置 | 改成什么 |
|---|---|
| `[search].queries` | 你要搜的关键词（画像生成时 DeepSeek 会顺便给你一份） |
| `[search].city` | 城市代码，默认北京 |
| `[job_filter].require_city` | 工作地点必须包含的字，如 `"上海"` |
| `[job_filter].min_daily_wage` | 日薪下限 |
| `[job_filter].prefer_districts` | 想优先的行政区，不需要就清空 |
| `[source].expect_tabs` | 你在 BOSS 上设的求职期望标签名，没有就清空 |

### 5. 跑起来

```bash
python run.py doctor                          # ① 自检：配置 → API → 浏览器 → 视觉链路
python run.py login                           # ② 扫码登录，登录态存进独立 profile
python run.py greet --limit 1                 # ③ 演练一条：看筛选和选中谁（不点击）
python run.py greet --live --limit 1 --yes    # ④ 真发一条，盯着浏览器确认
python run.py greet --live --yes              # ⑤ 按额度连续跑
python run.py greet --auto                    # ⑥ 无人值守：投到平台额度用完，出错自动重启
python run.py greet --keywords "大模型算法 Agent"  # 只搜这几个词（不用改 config）
python run.py stats                           # 看历史记录
```

**第一次务必按 ①→②→③→④ 的顺序走。**

## 生成求职者画像（用 DeepSeek 网页版）

`resume/kb.md` 是一个普通 Markdown 文件，写的是「你能投哪些岗位族、各自优先级如何」。
每扫一屏职位，它会被原样拼进提示词，模型据此给每个岗位判档位。程序只读它、从不改写它。

**职业梯度**（档位）是固定的五档 + 不可用，程序靠这几个词排序，名字不能改：

| 档位 | 含义 | 默认排序分 |
|---|---|---|
| 最匹配 | 简历里有直接对应项目 / 经历的方向 | 3.0 |
| 次匹配 | 技能栈大部分能对上的相邻方向 | 2.0 |
| 可转投 | 能投、但匹配度一般的保底方向 | 1.0 |
| 产品 | 产品经理类岗位（日薪最低值 ≥800 才投，可调） | 3.0 |
| 测试 | 测试 / 测试开发（日薪最低值 ≥800 按 3.0，否则降为可转投） | 3.0 |
| 不可用 | 哪一档都落不进去 → 不投 | — |

排序分和门槛在 `config.toml` 的 `fit_scores` / `fit_min_low_wage` / `fit_fallback` 里调。
不想投产品或测试，把对应档位从 `fit_scores` 里删掉即可。

### 操作步骤

1. 打开 [chat.deepseek.com](https://chat.deepseek.com)，建议打开「深度思考」。
2. 点输入框旁的 📎 上传你的简历（PDF / Word / 图片都可以）。
3. 把下面整段提示词粘进去发送。
4. 把回复里**第一部分**（`# 求职者画像与可投岗位族` 开始的 Markdown）保存为 `resume/kb.md`（UTF-8 编码）。
5. 把**第二部分**的关键词列表替换进 `config.toml` 的 `[search].queries`。
6. 通读一遍 `kb.md`，删掉你不想投的方向、补上想投的，再跑 `python run.py greet --limit 1` 演练看看判档准不准。

格式可以参考仓库里的示例：[`resume/kb.example.md`](resume/kb.example.md)。

### 提示词（复制整段）

````text
你是一位资深的技术招聘顾问。我上传了我的简历，请你仔细阅读后，为我生成一份「求职者画像」，
它会被一个自动投递程序当作知识库使用：程序每看到一个 BOSS 直聘上的岗位，就让 AI 拿岗位的
标题和职位描述跟这份画像逐条对比，判断这个岗位属于哪一档、要不要投。

请严格按下面的要求输出两部分内容。

==================== 第一部分：求职者画像（Markdown） ====================

用一个 ```markdown 代码块输出，结构必须是：

# 求职者画像与可投岗位族

> 这段文字是判断岗位是否可投的**唯一依据**。扫描到岗位后逐条对比，
> 落入下面任一岗位族 = 可投，按「投递优先级」决定先后。

## 核心岗位族
（我简历里有直接项目 / 实习经历支撑的方向，3~6 个）

## 相邻岗位族
（技能能迁移过去、但没有直接经历的方向，2~6 个）

每个岗位族写成这样：
- **岗位族名称 / 常见同义岗位名**
  关键技术词与技能点，用顿号分隔，尽量写招聘 JD 里会出现的原词（框架、算法、工具、业务名词）。
  （对应项目：简历里的项目或实习名称）

## 投递优先级
- **最匹配**：……（列出岗位族名称）
- **次匹配**：……
- **可转投**：……
- **产品**：……（产品经理类；我不适合或不想投就写「无」）
- **测试**：……（软件测试 / 测试开发；不适合就写「无」）
  —— 产品、测试两档只看岗位方向归档；薪资门槛由程序判断，你不用管薪资

## 明确不投
（容易和我的方向混淆、但其实不该投的岗位，例如名字相近但技术栈完全不同的方向；以及非技术岗）

## 可写岗位标题（同义词参考）
（招聘方可能使用的各种岗位标题写法，用 / 分隔）

规则：
1. 「投递优先级」里只能使用 最匹配 / 次匹配 / 可转投 / 产品 / 测试 这五个档位名，不要改名、不要新增档位。
2. 档位划分要体现职业梯度：最匹配 = 有直接经历、竞争力最强；次匹配 = 技能大部分能对上；
   可转投 = 保底可投但竞争力一般。宁可把方向放低一档，也不要高估。
3. 只依据简历里真实存在的内容，不要编造我没做过的项目和技能；可以合理推断相邻方向，
   但要放在「相邻岗位族」里。
4. 关键技术词要具体（如「LangGraph、FAISS、Cross-Encoder 重排序」而不是「熟悉 AI」），
   因为程序是拿它跟 JD 的技术要求做比对的。
5. 不要写入我的姓名、电话、邮箱、学校、身份证号等个人身份信息，只写能力和方向。

==================== 第二部分：搜索关键词 ====================

用一个 ```toml 代码块输出 BOSS 直聘搜索关键词，格式如下，按投递优先级从高到低排列，
共 20~40 个，每个关键词 2~6 个字、是求职者在搜索框里会输入的词（不用加「实习」二字）：

queries = [
    # ---- 最匹配 ----
    "关键词1", "关键词2",
    # ---- 次匹配 ----
    "关键词3",
    # ---- 宽口径（一次能搜出一大批，交给档位判断）----
    "关键词4",
    # ---- 产品 / 测试 ----
    "关键词5",
    # ---- 可转投 ----
    "关键词6",
]

最后用三五句话告诉我：你认为我最有竞争力的方向是什么，以及画像里哪些地方建议我人工确认。
````

> 简历和画像都只留在你本机：`resume/` 目录除了示例文件外全部被 `.gitignore` 忽略。
> 想改投递范围、加岗位族、调优先级，直接改 `kb.md`，下次运行立即生效。

## 它怎么工作

```
   截图  →  叠加归一化网格  →  交给 DeepSeek  →  拿回坐标  →  CDP 点击
     ↑                                                          │
     └──────────────────── 循环直到任务完成 ──────────────────────┘
```

**只做一件事：点「立即沟通」。** 点了之后平台会自动发出默认招呼语并附上在线简历，
程序到此为止，**不进聊天页、不打字**，后续对话由你自己接管。

### 为什么走视觉而不是 DOM

| 问题 | DOM 方案的后果 | 视觉方案 |
|---|---|---|
| 列表页薪资**字体加密**（私有区字符 U+E000–F8FF） | 抓到一堆乱码 | 截图里是正常数字 |
| 「立即沟通」按钮校验 `event.isTrusted` | JS 注入点击被拒，甚至触发封禁 | CDP `Input.dispatchMouseEvent` 产生可信事件 |
| 页面结构频繁改版 | 选择器一改全废 | 页面怎么改都不影响 |

代价是慢（每个职位 4~8 次模型调用），对每天百来条的量级可以接受。

### 坐标怎么保证准

- DeepSeek 服务端会把图片缩放到约 1300×1300 等效像素，直接报像素坐标会对不上。
- 所以在**页面里**画一层 canvas 网格，刻度标成 0–1000 的归一化值，模型读到的刻度就是要返回的数字，与缩放无关。
- 小目标走**两段式定位**：先粗定位，再把区域裁出来放大、画更细的网格重问一次。
- 筛选器、卡片、弹窗按钮优先**按页面文字取外框**（只读几何位置，点击仍是 CDP 可信事件），查不到再退回纯视觉。

### 为什么不用 Playwright / Selenium

1. **指纹**：Playwright 连上 CDP 后会往页面注入 utility script，是明显的自动化特征。原生 CDP 不注入任何东西。
2. **target 归属**：实测遇到过 Playwright 截图和操作落在不同标签页的情况；原生 CDP 一个 target 一个连接，没有歧义。

代码刻意不调用 `Runtime.enable` / `Page.enable` / `Debugger.enable`，这几个正是最主流的 CDP 检测点。

### 两个必须处理对的细节

**给谁打招呼。** 页面是「左边卡片 + 右边详情」，右侧按钮属于**当前选中**的卡片，不一定是程序挑中的那个。
所以每次先点开目标卡片，再定位按钮，并**核对按钮所属职位与目标一致**，不一致就跳过，宁可不发也不打错人：

```
▸ 具身智能导航算法实习生 @ 某某智能  600-800元/天
  ! 按钮所属「图数据库工程师」与目标「具身智能导航算法实习生」不符，跳过以免打错人
```

**弹窗选错按钮会闯进聊天页。** 打完招呼弹出「留在此页 / 继续沟通」，后者会跳进聊天页。
程序让模型标注每个按钮**会不会离开列表页**，并按页面文字点「留在此页」。

## 配置说明

所有配置都在 `config.toml`，改完下次运行立即生效。`[source]` 决定**去哪找**，`[job_filter]` 决定**发不发**。

### 职位来源 `[source]` / `[search]`

```toml
[source]
mode = "both"                      # recommend 推荐流 / search 关键词搜索 / both 两者都走
recommend_last = true              # 先搜关键词，推荐流放最后补漏
expect_tabs = ["算法工程师(北京)"]  # 「推荐」旁边你的求职期望标签名，没有就 []

[search]
queries  = ["大模型算法", "Agent", ...]   # 按投递优先级排
job_type = "1902"                         # 1902 = 实习，直接写进搜索地址
city     = "101010100"                    # 北京
```

常用城市代码：全国 `100010000` / 北京 `101010100` / 上海 `101020100` / 广州 `101280100` /
深圳 `101280200` / 杭州 `101210100` / 成都 `101270100`。

推荐流加了实习筛选后通常只有二三十个岗位，想投到平台每日额度必须靠关键词搜索补量。
每个来源翻到页脚就换下一个，搜到的岗位照样过全部筛选。

一个关键词连续几屏都是**新岗位却一个都不能投**时，只跳过这个词、换下一个，
不会因此结束整轮任务；连续 `limits.max_dry_sources` 个来源都没投出去才收工
（默认 `0` = 把所有关键词走完）。

**临时只搜指定的关键词**（不用改配置）：

- QQ：`/投递 大模型算法 Agent`（实发）、`/演练 大模型算法`（演练）；
  或先 `/关键词 大模型算法 Agent` 设成默认，之后 `/投递` 只搜这几个词，
  `/关键词 清空` 恢复 config。
- 命令行：`python run.py greet --keywords "大模型算法 Agent" --live`。

指定关键词时**只搜这些词**，不掺推荐流。任务开始前会先推一条关键词清单。

### 筛选规则 `[job_filter]`

**第 0 层：BOSS 自带筛选器**（`boss_filters = [["求职类型", "实习"]]`）——先把池子换对，不能省。

**第 1 层：硬条件**（不满足就不发）

| 条件 | 默认 | 说明 |
|---|---|---|
| `require_internship` | `true` | 只要实习岗（看标题和标签，校招全职不算） |
| `min_daily_wage` | `300` | 日薪下限，**区间取中位数** |
| `require_city` | `"北京"` | 地点不含这几个字就跳过 |
| `allow_unparsable` | `false` | 薪资读不出来（如「面议」）时是否照发 |

**第 2 层：档位 + 地点软排序**

```toml
fit_scores       = { "最匹配" = 3.0, "次匹配" = 2.0, "可转投" = 1.0, "产品" = 3.0, "测试" = 3.0 }
fit_min_low_wage = { "产品" = 800, "测试" = 800 }   # 日薪最低值达标才按本档分投
fit_fallback     = { "测试" = "可转投" }            # 不达标降到哪档；没写 = 不投
prefer_districts      = ["海淀区", "海淀"]         # 命中就加分，只影响先后
prefer_district_bonus = 1.0
```

表里没有的档位 = 不打招呼。每屏扫描后按「档位分 + 地区分」从高到低发。

### 薪资折算

一律先折算成**日薪**再比，月薪按 **21.75** 天/月（`work_days_per_month`）：

| 原始写法 | 折算结果 |
|---|---|
| `400-500元/天` | 400–500，中位 450 |
| `6-8K` | 276–368，中位 322 |
| `13-26K·14薪` | 先按 14 个月年化，再摊到日 |
| `20-30万/年` | 767–1149 |
| `面议` | 解析不出 → 默认跳过 |

### 安全阀 `[limits]` / `[safety]`

| 配置项 | 默认 | 说明 |
|---|---|---|
| `safety.dry_run` | `true` | 演练模式，只筛选不点击；`--live` 覆盖 |
| `safety.stop_on_captcha` | `true` | 遇到验证码立即停机交还人工 |
| `limits.daily_cap` | `200` | 本地兜底上限；真实额度以平台提示为准（约 150/天） |
| `limits.min_interval_sec` / `max_interval_sec` | `25` / `60` | 两次打招呼间隔（三角分布随机） |
| `limits.max_empty_scans` | `6` | 单个来源连续几屏挑不出岗位就换下一个 |
| `limits.max_dry_scans` | `8` | 单个关键词连续几屏都是新岗位却都不能投，就跳过这个词 |
| `limits.max_dry_sources` | `0` | 连续几个来源一条都投不出去才收工；`0` = 全部走完 |
| `limits.active_hours` | `[0, 24]` | 运行时段；建议收紧到 `[9, 21]`，凌晨批量操作最容易被标记 |

另外：按「职位标题 + 公司」去重，同一职位绝不重复打扰；读不全职位名的卡片直接跳过；
点击类 CDP 命令断线后绝不重试，避免重复点击。

## 日常使用

双击 `daily_greet.bat`（= `python run.py greet --auto`），不需要盯着：

- **停在平台额度上**：每次点完读一遍页面文字，出现「次数已用完」「已达上限」就停。
- **出错自动重启**：CDP 断线、模型调用失败 → 等 60 秒重开，最多连续 5 次；已发过的不会重发。
- **这些情况会停下等你**：验证码（人工过掉后重跑）、登录失效（先 `python run.py login`）。
- **日志**在 `logs/greet_<时间>.log`，截图在 `shots/<run_id>/`。

每天定时跑，用 Windows 任务计划程序（路径按实际改）：

```
schtasks /Create /TN auto_boss /SC DAILY /ST 09:05 /TR "C:\path\to\Auto_BOSS_Visual\daily_greet.bat"
```

浏览器保持登录态（独立 profile 会记住），电脑别睡眠。

## QQ 机器人（可选）：小号推送、大号遥控

用一个 QQ 小号当机器人：**每投出一条就私聊推给你的大号**，任务结束推总结；
你在大号上给小号发指令，就能远程开始 / 停止投递、查看进度。

小号用 [SnowLuma](https://github.com/SnowLuma/SnowLuma) 托管（任何 OneBot v11 实现都行，NapCat / LLOneBot 也可以），
它开一个**正向 WebSocket**，程序当客户端连上去，不需要额外装 Python 包。

> ⚠️ 用第三方协议端登录 QQ 同样违反腾讯协议，小号有被风控的可能。**别用重要的号当机器人。**

**第一次配置：**

1. 把 SnowLuma Windows 版解压到项目下的 `SnowLuma/`（已在 `.gitignore` 里）。
2. 运行 `python run.py bot`，控制台会打印 WebUI 初始密码。打开 http://127.0.0.1:5099 ，
   用 `admin` + 该密码登录，**同意 EULA 并改密码**。
3. 在弹出的 QQ 里登录小号，到 WebUI 的 OneBot 网络配置里确认有一个「WebSocket 服务端」，端口 3001，记下 access token。
4. 大号和小号互加好友。
5. `.env` 里填：
   ```ini
   ONEBOT_TOKEN=上面的token
   OWNER_QQ=你的大号QQ号
   ```
   `config.toml` 的 `[qq]` 里确认 `enabled = true`、`ws_url = "ws://127.0.0.1:3001"`，
   QQ 安装路径不同的改 `qq_path`。
6. 再运行 `python run.py bot`，大号会收到「已上线」。

`run.py bot` 启动时会自动拉起 SnowLuma 和 QQ（`[qq].auto_launch`），两者都不建窗口。
想开机自启又不想任务栏里挂黑窗口，在「启动」文件夹（Win+R → `shell:startup`）里放一个
`auto_boss_bot.vbs`：

```vbs
Set sh = CreateObject("WScript.Shell")
sh.CurrentDirectory = "D:\tools\auto_boss"
d = Year(Date) & Right("0" & Month(Date), 2) & Right("0" & Day(Date), 2)
sh.Run "cmd /c start_bot.bat >> logs\bot_" & d & ".log 2>&1 <nul", 0, False
```

窗口样式 `0` = 隐藏；`<nul` 让 `start_bot.bat` 末尾的 `pause` 不会傻等。
bot 和 SnowLuma 的输出分别落在 `logs/bot_*.log` 和 `SnowLuma/logs/`。
bot 出现未预期异常时会自动把最近日志推给大号；**断网时发不出去的通知会存进
`logs/qq_outbox/`，恢复连接后自动补发**。

**指令（大号私聊小号，以 `/` 开头）：**

| 指令 | 作用 |
|---|---|
| `/投递` | 实发，投到平台额度用完（= `greet --auto`） |
| `/投递 10` | 实发，本次最多 10 条 |
| `/投递 大模型算法 Agent` | 实发，**只搜**这几个关键词（不走推荐流） |
| `/搜索 关键词` | 同 `/投递 关键词` |
| `/演练 5` | 只筛选不发送，最多 5 条 |
| `/演练 大模型算法` | 只搜这几个关键词，演练 |
| `/关键词` | 看当前检索关键词（config 的或 QQ 指定的） |
| `/关键词 大模型算法 Agent` | 设定下次任务的检索关键词，之后一直沿用 |
| `/关键词 清空` | 恢复 config.toml 的 `[search].queries` |
| `/停止` | 当前这条处理完就收尾；150 秒没退出就强制结束 |
| `/状态` | 是否在跑、跑了多久、今日已投多少 |
| `/今日` | 今天投了哪些岗位 |
| `/统计` | 今日各状态计数 + 最近 5 次运行 |
| `/日志 20` | 最近一份运行日志的末尾 20 行 |
| `/重启` / `/关机` | 60 秒后重启 / 关闭电脑 |
| `/取消` | 撤销还没执行的重启 / 关机 |
| `/帮助` | 指令列表 |

- 只认大号私聊里以 `/` 开头的消息，其他一律不理。
- `/投递` 是实发，**不再二次确认**。
- 每次任务开始前会先推一条「本次检索关键词」（实发/演练、条数、是否走推荐流都在里面）；
  命令行、bat 跑 `greet` 时也会推。关键词之间用空格、逗号、顿号或竖线分隔都行。
- 推送不依赖 bot 进程：只要 `[qq].enabled = true` 且填了 `OWNER_QQ`，命令行 / bat 跑 `greet` 也会推送；SnowLuma 没开时投递照常进行。
- bat、命令行、QQ 三个入口共用一把操作系统文件锁，**同一时间只有一个任务操作浏览器**。

## 排查

| 现象 | 处理 |
|---|---|
| 截图是白的 / 是别的页面 | 截图前会 `bringToFront`，开着多个浏览器窗口时把别的最小化 |
| 坐标总是偏一点 | 看 `shots/<run_id>/` 的带网格截图；页面缩放不是 100% 就按 Ctrl+0 复位 |
| 「未能确认立即沟通按钮」 | 按钮不在当前屏 / 已沟通过 / 详情面板停在别的职位上，看存档截图确认 |
| 筛选器点成了「薪资待遇」 | 程序会核对实际展开的下拉，不对就关掉重试；连续两次失败退回卡片级过滤 |
| confidence 普遍很低 | 把 `deepseek.thinking` 设成 `true`，更慢但更稳 |
| 停在验证码上 | 正常行为，人工过掉后重跑，去重库保证不会重发 |
| 判档不准 | 改 `resume/kb.md`：给岗位族补 JD 原词、在「明确不投」里写清容易混淆的方向 |

## 成本

每个职位约 6 次模型调用、约 1 万 token（单张截图封顶约 1024 token）。按每天 100 条算是百万 token 量级，
单价见 [DeepSeek 定价页](https://api-docs.deepseek.com/quick_start/pricing)。
想省钱：减少 `queries`、调小 `max_empty_scans` / `max_dry_scans`、
把 `max_dry_sources` 设成 10~15（不必把所有关键词走完）、保持 `deepseek.thinking = false`。
